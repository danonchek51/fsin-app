# Миграция существующей рабочей среды в новый шаблон

Этот маршрут подходит для любого старого проекта. Он переносит ценное содержание, а не старую структуру workflow.

## 1. Заморозьте источник

Сделайте read-only snapshot/архив и запишите его revision. Не исправляйте старую среду во время миграции: иначе невозможно отличить источник от результата.

## 2. Разделите материалы по назначению

| Переносить после проверки | Не переносить как основу |
| --- | --- |
| код, тесты, утверждённые requirements, принятые решения, полезные docs, evidence | `_bmad/`, `.agents/`, generated skills, render-cache, user/machine-local config, `.git/`, transcripts |

Старые specs сначала помещайте в `legacy/` и создавайте mapping: старый путь → действующий contract или причина, почему материал больше не активен.

## 3. Создайте новую среду отдельно

Создайте новый репозиторий из этого шаблона, выполните `INIT-001`, выберите один lane и установите BMAD с нуля. До этого шага не импортируйте старые artifacts.

## 4. Восстановите один текущий work item

Не переносите весь backlog. Выберите ближайший незавершённый результат, создайте для него один source contract и, если нужна реализация, один implementation contract. В `NOW.yaml` оставьте только следующий action для него.

## 5. Проверьте независимость

Клонируйте новую среду либо откройте чистый чат без старой истории. Пройдите `START-NEW-CHAT.md`, затем `tools/verify-workspace.ps1`. Если для продолжения нужен старый чат или неперемещённый локальный путь, это migration gap: зафиксируйте его и перенесите минимальный канонический факт.

## 6. Закройте переход

Когда новый workflow прошёл хотя бы один полный цикл contract → implementation → verification → handoff, объявите старую среду read-only legacy. Не удаляйте её, пока новый репозиторий не находится в private remote и не проверен на второй машине/аккаунте.
