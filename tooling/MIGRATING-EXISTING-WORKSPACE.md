# Миграция существующей рабочей среды в новый шаблон

Этот маршрут переносит ценное содержание, а не старую структуру workflow. Сначала выберите один из двух безопасных вариантов.

| Вариант | Когда выбирать | Результат |
| --- | --- | --- |
| **Исправить на месте** | Репозиторий и подтверждённый remote здоровы, а проблема — в правилах, runtime или маршрутизации | Сохраняются история и URL; добавляется один корректирующий checkpoint и новый компактный процесс |
| **Пересобрать копию** | История, remote или owners конфликтуют так, что им нельзя доверять, либо требуется другой delivery engine | Старый репозиторий остаётся read-only legacy; новая среда начинает чистую историю только по явному решению владельца |

Не создавайте «чистую» историю только потому, что старые artifacts выглядят сложными: это смена continuity и требует отдельного явного решения владельца с целью и точным URL.

## 1. Заморозьте источник

Сделайте read-only snapshot/архив и запишите его revision. Не исправляйте старую среду до того, как сохранён baseline: иначе невозможно отличить источник от результата.

## 2. Разделите материалы по назначению

| Переносить после проверки | Не переносить как основу |
| --- | --- |
| код, тесты, утверждённые requirements, принятые решения, полезные docs, evidence | `_bmad/`, `.agents/`, generated skills, render-cache, user/machine-local config, `.git/`, transcripts |

Старые specs сначала помечайте historical/legacy и создавайте mapping: старый путь → действующий contract или причина, почему материал больше не активен.

## 3. Примените компактный контур

### Исправление на месте

1. Сохраните подтверждённый remote и историю; не меняйте `continuity.*`.
2. Замените только общие process-файлы: project `AGENTS.md`, `control/`, `handoffs/`, validator и пользовательскую инструкцию из этого шаблона.
3. Оставьте один текущий work item и один `NOW.next_action`; устаревшие contracts удалите из его `input_paths` и явно отметьте как historical в charter.
4. Создайте один handoff checkpoint для самой миграции, отправьте его и пройдите postcommit. Далее обычные commits не требуют нового handoff, пока нет настоящей границы передачи.

### Пересборка копии

Создайте отдельный репозиторий из шаблона, выполните `INIT-001`, выберите один lane и установите BMAD с нуля. До этого шага не импортируйте старые runtime/artifacts. Перенесите только один ближайший незавершённый результат как новый contract; не переносите весь backlog.

## 4. Проверьте независимость

Клонируйте результат либо откройте чистый чат без старой истории. Пройдите `START-NEW-CHAT.md`, затем `tools/verify-workspace.ps1`. Если для продолжения нужен старый чат или неперемещённый локальный путь, это migration gap: зафиксируйте его и перенесите минимальный канонический факт.

## 5. Закройте переход

Когда новый workflow прошёл хотя бы один реальный цикл результата → verification и достиг meaningful checkpoint для передачи, объявите старую среду read-only legacy. Не удаляйте её, пока результат не находится в private remote и не проверен на второй машине/аккаунте.
