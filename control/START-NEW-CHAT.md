# Промпт для чистого чата

Предыдущий агент обязан выдать эту фразу в навигационной сводке, когда выбрал режим `новый чат` после завершённого action. Новый чат не является наказанием или ручной догадкой: это нормальная граница, на которой handoff уже сохранил нужный контекст.

```text
Работай по каноническим файлам проекта, а не по предположениям из прошлых чатов.

1. Полностью прочитай AGENTS.md, control/WORKSPACE-PROFILE.yaml, control/NOW.yaml, control/STATE-MACHINE.md и docs/PROJECT-CHARTER.md.
2. Если `last_handoff` в NOW не `null`, прочитай обязательный путь как снимок; при расхождении следуй NOW и каноническим BMAD artifacts.
3. Открой только next_action.input_paths и файлы, на которые они непосредственно ссылаются.
4. Выполни ровно next_action.id. Не начинай соседнюю работу, следующую фазу или иной workflow.
5. Если входа недостаточно, нужны решения владельца или есть конфликт владельцев, не продолжай: установи `dispatch_state: blocked`, запиши `blocker` и `resume_state`, затем сделай следующим action конкретный ask-owner с одним вопросом.
6. После успешного action сохрани evidence, обнови владельца изменённого факта, NOW.yaml и новый immutable handoff. Запиши путь handoff в `NOW.last_handoff`; его next-action ID обязан совпасть с NOW. Добавь commit marker handoff в отдельный Git commit, отправь его в private remote и затем пройди post-commit проверку.

Чат — не память проекта. Не добавляй второй delivery module, Loop, Build Auto или внешний SDD engine, если это не закреплено в профиле и решении.
```
